# Null-system triage, group nb-01

Kind b (PASS although the subject was called and returned the stub's failure): 95 assertions.

Decisions: VACUOUS 0, LEGIT 75 (of which 26 got a control added to the test), WEAK 20 (19 strengthened, 1 left for the owner).

"re-verified yes" means: the null control (`ci/nullsys.sh run /tmp/null1 --only`) no longer gives PASS (FAIL, or INSPECT for a disputed assertion), and the normal run on this machine gives the verdict the assertion had (PASS, or the FAIL already recorded in known/ for psiginfo.007 and sysconf.001). Lint is clean except "declares no MUTANT".

Tooling note (not changed here): the stub generator treats typedef'd handles (wctype_t, wctrans_t, locale_t) as integers and fails with -1 instead of 0, so tests that only compare a handle with 0 pass on the control. Some failure values also coincide with real ones on this machine: -1 is EOF, WEOF and EAI_BADFLAGS, and the stubbed ferror() returns -1, which is non-zero.
