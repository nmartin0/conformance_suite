## Recurring patterns

1. Interactive-shell tests (`sh -i <file`) all time out on this system: pcexec makes a process group, not a session, so under a controlling terminal the interactive shell must stop itself. Suggested harness change (not made): `setsid()` in core/pcexec.c; or run those tests on the pcpty helper.
2. pcpty without `-r` loses the first typed line on a program that flushes input while starting (ex here); every pty test of a full-screen or line editor should use `-r`.
3. Required utilities absent (gettext, msgfmt, iconv) are SYSTEM, as in the Linux tables; tests that only need them for setup stay UNRESOLVED (ENV).
4. Failure messages that print the tested program's stderr through `head -c` hide the cause where `head -c` is missing; the ex ones are fixed here, other modules still use it.
5. Signals sent at once after `cmd &` (kill, and wait.006 outside this list) are racy on a shell whose child takes the signal before exec.
6. The utility page for the old mailx (Mail 8.1.2) is mostly older than the 2024 text: since-2024 assertions (SHELL -c --, next on an unread current message) fail there by design.
7. The ex group is UNKNOWN as a whole: the editor exits 1 for every non-terminal script, which looks like one environmental or TERM-related cause; the stderr from the next run settles it.
